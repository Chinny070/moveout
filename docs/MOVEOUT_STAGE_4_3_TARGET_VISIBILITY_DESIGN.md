## Proposed observation model (not implemented)

Bind every observation to an explicit target nomination made before image interpretation. Proposed nomination fields are deterministic inspection metadata:

| Field | Meaning |
|---|---|
| `target_id` | Stable target reference within an Area/Item and Inspection; never generated by the vision model. |
| `target_description` | Bounded human-entered description, such as “the crack near the upper-left wall outlet”; immutable for the frozen evaluation request. |
| `target_region_ref` | Optional user-marked region/anchor on a nominated overview image, tied to that evidence ID and digest. It is a locator claim, not proof of physical identity. |
| `required_surface_id` | The Area/Item the target belongs to. |

The vision result for each individual frozen evidence item should use independent dimensions rather than infer target visibility from visible surface pixels:

| Proposed field | Bounded values | Question answered |
|---|---|---|
| `surface_visibility` | `VISIBLE`, `PARTIAL`, `NOT_ESTABLISHED`, `UNCERTAIN` | How much of the named overall surface is visible? |
| `target_visibility` | `SUFFICIENT`, `PARTIAL`, `OBSTRUCTED`, `OUTSIDE_FRAME`, `INSUFFICIENT_CLARITY`, `NOT_LOCATABLE`, `UNCERTAIN` | Can the nominated target region itself be assessed in this image? |
| `foreground_obstruction` | `PRESENT`, `ABSENT`, `UNCERTAIN`, `NOT_APPLICABLE` | Does an object in front of the surface cover any material portion of the nominated target? |
| `target_frame_coverage` | `IN_FRAME`, `PARTLY_OUTSIDE`, `OUTSIDE`, `UNCERTAIN` | Is the nominated target within the image boundaries? |
| `target_clarity` | `ADEQUATE`, `INADEQUATE`, `UNCERTAIN` | Is detail/resolution/focus/lighting adequate for the requested bounded assessment? |
| `target_location_confidence` | `LOCATED`, `NOT_LOCATABLE`, `UNCERTAIN` | Can the model map the user-nominated target to pixels without inventing a target? |

This model can represent the Stage 4.2 image without contradiction: overall `surface_visibility=PARTIAL` or `VISIBLE` according to the defined surface-coverage threshold; `target_visibility=OBSTRUCTED`; `foreground_obstruction=PRESENT`; `target_frame_coverage=IN_FRAME`; and `target_clarity=ADEQUATE` for the visible pixels. The target is hidden by an object, not outside the frame. If the target cannot be located, record `NOT_LOCATABLE`/`UNCERTAIN` rather than guess which visible wall patch is intended.

Enum labels, quantitative coverage thresholds, and whether a target polygon can be represented within current GenVM constraints remain open design choices. A model output never defines or changes the user nomination.

## Deterministic safety invariants

These are protocol validation rules proposed for a later implementation; the model's visual answer is not itself deterministic truth.

1. **No confident absence without target coverage.** A defect-presence observation of `NO` is permitted only when `target_visibility=SUFFICIENT`, `target_frame_coverage=IN_FRAME`, `foreground_obstruction=ABSENT`, `target_clarity=ADEQUATE`, and target location is established. Otherwise feature presence/absence is `UNCERTAIN` or the result is unresolved.
2. **Positive observations are local.** A clearly visible defect may be recorded as a bounded positive observation only if its pixels are visible and target/location linkage is adequate. It does not imply the unseen portion is defect-free.
3. **Occlusion is not crop.** `foreground_obstruction=PRESENT` denotes a foreground object/obstacle hiding the target while it lies within frame. `target_frame_coverage=OUTSIDE` / `PARTLY_OUTSIDE` denotes boundary clipping. They are independent and may not be substituted for one another.
4. **Unrelated furniture does not invalidate a target.** Furniture outside the nominated target region leaves `foreground_obstruction=ABSENT` for that target, even if it occupies other image pixels. The model must not flag an entire image merely because furniture is present.
5. **No invented target.** Missing, vague, or conflicting target nomination, or inability to map it to image pixels, yields `NOT_LOCATABLE`/`UNCERTAIN`. The model cannot select a different crack, wall, or similar-looking patch to fill the gap.
6. **A later image resolves only demonstrated coverage.** A new image can clear a previous visibility blocker only if it links to the same immutable target nomination and the target is demonstrably in frame, unobstructed, and clear in that new image. A new URL, matching room label, or user assertion alone does not prove coverage or same physical location.
7. **Conflicts remain unresolved.** Conflicting image interpretations or inconsistent overview/close-up target mapping produce an unresolved aggregate. Do not choose the most confident output or average enum values into certainty.
8. **No consequential promotion.** An observation never establishes liability, new damage, worsening, repair responsibility, normal wear, or deposit deduction. Existing deterministic promotion gates and human challenge boundaries remain separate and are not expanded by this design.

For a blocked target, the overall observation status should be `UNRESOLVED_VISIBILITY` (or an equivalent existing inconclusive status), preserving each image-level result and its evidence reference. It must not manufacture a defect-negative observation.

## Guided evidence capture

Smallest practical capture flow:

1. **Nominate.** In the frozen Inspection, the user selects an existing Room and Area/Item and identifies a target (e.g. a visible mark or a specified patch to inspect). Store target description/ID and any user-marked overview region as metadata. Keep author and timestamp; treat the nomination as a claim, not visual truth.
2. **Overview.** Request a clear room/area overview with stable landmarks, sufficient context, and the nominated surface in frame. Submit as a new Evidence record linked to the Inspection, Area/Item, and `target_id`.
3. **Closer view if needed.** If overview target visibility is insufficient, request a closer photograph centered on the same target and include overlap landmarks or the annotated target cue where practical. Store as another Evidence record with the same target ID and an explicit `capture_slot`/`supplements_evidence_id` relationship. Do not overwrite the overview.
4. **Assess.** Independently evaluate each frozen image's surface visibility, target visibility, obstruction, frame coverage, clarity, and target-location confidence. Compare the close-up to the target nomination and overview landmarks. A close-up resolves the blocker only when the target is mapped with adequate support; otherwise remain unresolved.
5. **Resolve or retain unresolved.** If adequate target coverage is not established, ask for another capture or append an `UNRESOLVED_VISIBILITY` observation that records the missing predicate. Do not block saving the inspection; do block any absent-defect inference dependent on the target.

Both photos link to the same frozen `inspection_id`, `room_id`, `area_item_id`, and `target_id`, but each keeps its own immutable Evidence ID, source URL, expected digest, capture metadata, freeze state, and provenance verification. Freeze each evidence record before interpretation; later additions are append-only and trigger a new observation version referencing both old and new records.

Shared identifiers do not prove two images depict the same physical place. Visual continuity is a separate uncertain observation supported by landmarks, target shape/position, and overlap; user capture-slot links express intent only. If same-area/target correspondence cannot be established, the close-up cannot resolve the prior view and aggregate status stays unresolved.

## Validator equivalence requirements

Each active validator must independently retrieve and digest-check every referenced frozen image and independently evaluate the nominated target. Apply the same bounded normalization/semantic checks to the leader and each validator candidate.

Require exact equality for at least:

- property/tenancy/inspection/room/area IDs, target ID and nomination version/digest;
- evidence IDs, source digests, provenance-verification IDs, image order, and the requested capture/continuity references;
- `surface_visibility`, `target_visibility`, `foreground_obstruction`, `target_frame_coverage`, `target_clarity`, and `target_location_confidence` for each evidence image;
- any downstream safety-critical target feature-presence field and aggregate unresolved/observable status.

Do not allow secondary-field tolerance for target visibility, obstruction, crop/frame coverage, evidence identity, or target identity. Any mismatch, retrieval digest mismatch, malformed schema, contradictory field combination, or validator failure must leave the evaluation unresolved/rejected; the leader proposal is not a fallback truth. Inactive/IDLE validators are not counted as independent interpretations. Preserve the bounded candidate result and consensus outcome separately if the runtime supports it; do not imply receipts expose private candidate values when they do not.

Even exact validator agreement does not establish physical truth: model outputs may be correlated. Equivalence addresses protocol disagreement only.

Local tests should be split into two clearly labeled groups:

- **Deterministic schema/invariant tests:** supplied structured candidates and metadata; verify allowed combinations, fail-closed normalization, no promotion, exact-equivalence fields, evidence linkage, and append-only unresolved aggregation. These can prove code behavior only.
- **Visual-model evaluation:** blind model outputs against independently reviewed target boxes/regions and labels, including held-out views, occlusion, cropping, unrelated objects, lookalikes, shadow, and adversarial text. Report confusion counts and uncertainty; never describe a deterministic expected-value fixture test as a model pass.

## Limitations and open decisions

- A model's “target is visible” judgment is still semantic and may be wrong; deterministic consistency rules cannot detect every visual miss.
- No pixel-level coverage threshold or target-region annotation format is selected. Such geometry may be difficult to preserve across changed viewpoint and cannot by itself establish same-place identity.
- User-nominated descriptions/regions are claims. A close-up and overview need recognizable overlap/landmarks or another reviewed continuity method; same IDs alone do not prove continuity.
- Current hosted receipts do not expose each validator's full candidate output or per-image retrieval trace. Exact equivalence rules improve safety, but observability/audit limitations remain.
- Synthetic fixtures are narrow and do not establish real-world property-inspection accuracy. Rights-cleared, independently labeled, representative data and a blinded evaluation plan remain necessary.
- No API/runtime capability for structured polygon vision output, image registration, or cryptographic capture timestamps is assumed here.
